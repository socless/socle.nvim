*socle.txt*  Socle, the Chisel IDE language server, in Neovim

                                                                     *socle*
socle.nvim runs the Socle language server for Chisel projects built with
Mill. It adds a "View design" and a "Simulate" code lens above every ChiselSim
test. View design shows the test's design in a live panel in your browser;
Simulate runs the test with waveforms and shows them in Surfer.

The plugin downloads the pinned server release, checks its sha256 and starts
it next to Metals. Your tests and build are never modified. The server is
described in Socle's docs/ide-neovim.md:
https://github.com/socless/socle/blob/main/docs/ide-neovim.md

Requirements: Neovim 0.12, Java 21 or later, a Mill project (build.mill at
its root, and ./mill there or mill on PATH). To download the jar: curl, and
sha256sum or shasum. For Simulate: Verilator, and the Surfer app unless
wave_viewer is "surfer-panel". Windows is not tested: without sha256sum or
shasum, set `server_jar`.

When curl cannot download the jar, the plugin falls back to
`gh release download` (with a logged-in gh), or set `server_jar`.

==============================================================================
SETUP                                                          *socle-setup*

Nothing happens before setup() is called: >lua
    require("socle").setup({})
<
With lazy.nvim: >lua
    { "socless/socle.nvim", ft = "scala", cmd = "Socle",
      opts = { wave_viewer = "surfer-panel" } }
<
The server starts with the first Scala buffer of a Mill project (a build.mill
above the file). The first start downloads the jar, with a notice when it
starts and when the server is ready.

==============================================================================
OPTIONS                                                      *socle-options*

The defaults: >lua
    require("socle").setup({
      version = "0.25.2",   -- server release to download
      server_jar = nil,     -- a local jar: overrides version and download
      java = nil,           -- nil: $JAVA_HOME/bin/java, else "java"
      codelens = true,      -- show the lenses
      follow_cursor = true, -- the panel lights the class under the cursor
      open_panel = nil,     -- nil: vim.ui.open(url); a list: a command,
                            -- the url appended; or a function(url)
      notify_status = true, -- "design ready" and "simulating" notices
      settings = {},        -- sent to the server, see below
    })
<
                                                    *socle-settings*
The settings, sent to the server in camelCase. They go directly in the
options (flat: `wave_viewer = "surfer-panel"`) or under `settings`; a key in
both places takes the `settings` value. A key left out is not sent (the
server default applies). An unknown option or setting is warned about and
ignored.

  wave_flag                 ChiselSim wave option, `-D<flag>=1`. "emitVcd"
  surfer_command            the Surfer app's executable. "surfer"
  wave_viewer               "surfer", "surfer-panel" or "custom". "surfer"
  wave_viewer_command       command for "custom"; {file} is the trace
  waves_follow_selection    the selected module picks the signals. true
  waves_show_clock_reset    clock and reset lead the list. false
  waves_fold_bundles        "surfer-panel": bundles start folded. false
  waves_show_wires          include the Wires group. true
  waves_color_by_direction  inputs blue, outputs green. true
  waves_follow_delay_ms     delay before Surfer follows. 150
  schematic_colorize_components   colour the boxes by kind. false
  schematic_colorize_wires        colour the wires by bundle. false
  schematic_density         "compact", "comfortable" or "comfy". "comfortable"
  schematic_label_size      "normal", "large" or "xl". "normal"
  schematic_auto_optimize   lay views out with the optimize pass. true
  schematic_hint_bar        the hint bar under the schematic. true
  schematic_show_layers     draw verification layers. false
  schematic_hide            node kinds left out: "op", "reg", "const",
                            "mem", "fsm", "block". {}

wave_flag and surfer_command need server 0.16.0, the other wave settings
0.17.0, the schematic_* settings 0.18.0: an older
`version` gets one warning per such setting. A second setup() with new options
applies them by restarting the server; the open Scala buffers attach to the
new one.

                                                     *socle-version*
Each plugin release pins the server version it is tested against (0.25.2),
and the sha256 of its jar. The jar goes to
stdpath("data")/socle/socle-lsp-<version>.jar, downloaded once from the
GitHub release. The pinned jar must match the pinned sha256; a `version` you
set is checked against the release's SHA256SUMS. A failed download leaves
nothing behind, and is retried only on the next setup() or `:Socle update`.
Set `version` to run another release, or `server_jar` to run a local jar (no
download, no version check).

==============================================================================
COMMANDS                                                    *socle-commands*
                                                                    *:Socle*

:Socle view       Run the View design lens of the test at or above the
                    cursor (else the first one in the file).
:Socle simulate   The same with the Simulate lens.
:Socle panel      Open the last view's panel again.
:Socle update     Download the jar again, then restart the server on it (or
                    start one). The jar on disk is only replaced once the new
                    one verified: a failed update keeps it.
:Socle log        Open the LSP log, with the server's stderr, in a tab.
:Socle health     Run `:checkhealth socle`.

The browser opens once per panel URL; `:Socle panel` forces it again. The
lenses also run with `grx` or |vim.lsp.codelens.run()|.

==============================================================================
HEALTH                                                        *socle-health*

`:checkhealth socle` checks Neovim 0.12, that setup() was called, the java
in use (Java 21 or later, else an ERROR), the jar (the pinned one is hashed
again and must match the pinned sha256; a missing `server_jar` is an ERROR),
curl, sha256sum or shasum, whether gh is installed and logged in
(`gh auth status`), `./mill` or `mill` for the Mill project of the open Scala
buffers (else of the working directory), verilator, and the Surfer app when
wave_viewer needs it. The download tools only WARN when the jar still has to
be downloaded.

==============================================================================
METALS                                                        *socle-metals*

socle.nvim runs next to Metals or nvim-metals: both clients attach to the
same buffers. Socle offers no diagnostics, completion, hover or definition.
Code lenses are enabled for the socle client only, so Metals' lenses stay
as they are.
